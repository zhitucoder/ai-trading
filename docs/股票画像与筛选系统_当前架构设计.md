## 二、画像系统（单股画像）

### 2.1 API：`GET /api/profile/{stock_code}?refresh=false`

**流程：**
1. 先查 `stock_profiles` 表的 `profile_json` 缓存
2. 缓存存在且 `refresh=false` → 直接返回
3. 缓存不存在或 `refresh=true` → 调用 `generate_profile(code)` 实时计算并返回

```python
def get_profile(stock_code: str, refresh: bool = False):
    if not refresh:
        r = query("SELECT profile_json FROM stock_profiles WHERE stock_code=%s ORDER BY trade_date DESC LIMIT 1", [stock_code])
        if r and r[0]['profile_json']:
            return json.loads(r[0]['profile_json'])
    return generate_profile(stock_code)
```

### 2.2 画像引擎：`generate_profile(code)`

位于 `strategies/profile.py:1047-1172`，依次执行以下步骤：

#### 步骤1：获取基础信息
- `get_stock_name(code)` → 从 `stocks` 表取中文名
- `get_stock_sectors(code)` → 从 `stock_sectors` + `sectors` 取行业/地域/概念/风格分类

#### 步骤2：获取行情数据
- `get_klines(code, days=300)` → 从 `daily_kline` 取最近300个交易日数据
- 计算：最新价、涨跌幅、MA5/10/20/50/60/150/200、RSI14、成交量均线

#### 步骤3：获取财务数据
- `get_latest_financials(code)` → 连表查询 `fin_quarterly`（当期 + 上年同期）+ `fin_balance_sheet` + `fin_contract_bs`
- `get_prev_financials(code)` → 上一季度数据
- `get_annual_financials(code, years=10)` → 取每年12月31日的年报数据（营收、净利、毛利率）
- `get_quarterly_growth(code, quarters=20)` → 最近20个单季度的同比增速
- `get_rolling_growth(code)` → 最近4个季度（TTM）的滚动同比增速

#### 步骤4：计算指标标签
- `compute_indicator_tags(...)` → 技术指标标签（MA多头排列、RSI超买/超卖、成交量异动等）

| `ind.price_above_ma200` | 收盘价 > MA200 | |

| `ind.volume_surge` | 成交量 > 均量×1.5 | |

#### 步骤5：计算业务标签

| 标签ID | 含义 | 条件 |
|:---|:---|:---|

| `biz.financial_risky` | 财务风险 | 负债率 50%~70% |

| `biz.bullish` | 多头排列 | MA5>MA10>MA20>MA60 |

| `biz.tenbagger` | 十倍股 | 2021年低点至今涨超10倍 |
| `biz.strong_momentum` | 强势动量 | 价格在MA50和MA200之上 |
| `biz.weak_momentum` | 弱势动量 | 价格在MA50和MA200之下 |
| `biz.volume_price_up` | 价涨量增 | |
| `biz.volume_price_down` | 价跌量缩 | |

#### 步骤6：计算Minervini SEPA阶段

`compute_stage(...)` → 基于12个S2条件、7个S3条件等判定：

| 阶段ID | 阶段名 | 含义 |
|:---|:---|:---|
| `stage.s1` | 打底蓄势期 | 底部盘整，均线缠绕 |
| `stage.s1s2` | 过渡期 | 从底部向上突破初期 |
| `stage.s2` | 突围加速期 | 主升浪，MA多头排列 |
| `stage.s3` | 见顶派发期 | 高位震荡，成交量异常 |
| `stage.s4` | 衰败下跌期 | 均线空头排列，持续新低 |

每个阶段附带 `confidence` 值（0-99）。

#### 步骤7：计算综合评分

`compute_scores(biz_tags, stage)` → 输出 `tech_score` 和 `fund_score`（0-100）

```python
tech_score = 50  # 基准分
if stage == s2: +20
if stage == s1s2: +10
if stage == s3: -10
if stage == s4: -20
if multiple bullish signals: +若干
if multiple bearish signals: -若干
# 最终 clamp 到 0-100

fund_score = 50
if 营收增长 > 20%: +15
if 净利增长 > 20%: +15
if 负债率 < 30%: +10
if 毛利率提升: +10
# ... 类似规则
```

#### 步骤8：计算RS排名

`compute_rs_rank(code)` → 该股票250日收益率在全部股票中的百分位排名

## 三、多条件筛选系统

### 3.1 API：`POST /api/profiles/search`

**请求体结构：**
```json
{
    "stages": ["stage.s2", "stage.s1s2"],
    "tags": {
        "must": ["biz.bullish", "biz.boom_growth"],
        "must_not": ["biz.profit_decline"],
        "any": ["biz.strong_momentum"]
    },
    "tech_score_min": 70,
    "fund_score_min": 60,
    "revenue_growth_min": 20,
    "net_profit_growth_min": 10,
    "debt_ratio_max": 50,
    "contract_liab_min": 0,
    "contract_liab_max": 100,
    "rev_cagr_3y_min": 0,
    "profit_cagr_3y_min": 0,
    "page": 1,
    "page_size": 50,
    "sort_by": "fund_score",
    "sort_order": "DESC"
}
```

**SQL生成逻辑：**
1. 从 `stock_profiles` 查最新 `data_date`
2. 按 `stages` 过滤 → `p.stage_id IN (...)`
3. 按标签过滤 → `p.tag_<id> = 1`（must）、`p.tag_<id> = 0`（must_not）
4. 按数值范围过滤 → `p.fund_score >= fund_score_min` 等
5. `contract_liab_min/max` 通过 `JSON_EXTRACT(p.profile_json, '$.fin_data.contract_liab_to_assets')` 过滤
6. 分页排序

## 五、财务数据源表（画像系统使用）

| 表名 | 用途 | 查询方式 |
|:---|:---|:---|
| `fin_income` | 利润表 | 自连接算同比增速（营收、净利、核心利润） |
| `fin_balance_sheet` | 资产负债表 | 直接取负债率、固定资产等 |
| `fin_cash_flow` | 现金流量表 | 取经营现金流 |
| `fin_quarterly` | 单季度数据 | 自连接算单季同比（含毛利率增速） |
| `fin_contract_bs` | 合同负债 | 取合同负债/总资产比例（由外部脚本抓取） |
| `fin_ratios` | 财务比率 | 仅用于获取最新 `report_date`，不取值（字段损坏） |

**财务可靠性检查**（`profile.py:rev_reliable()`）：
1. 营收 > 0
2. `|净利润| < 营收 × 2`（防止金融股财报字段映射错误）
3. `营收 / 总资产 >= 0.1%`（剔除营收极少但资产庞大的金融企业）

## 六、关键设计决策

1. **缓存优先，按需刷新**：单股画像优先读缓存，批量刷新通过 `/api/profiles/refresh` 触发。避免每次请求都实时计算全部5,500只股票。

2. **标签扁平化存储**：57个标签用独立BOOLEAN列而非JSON数组，是为了支持数据库索引过滤——`/api/profiles/search` 需要在百万行级别快速过滤。

3. **JSON双存储**：既存标量列（用于筛选），又存JSON（用于展示）。冗余但实用。

4. **单线程批量刷新**：`profile_batch.py` 顺序处理5,500只股票，每次约30分钟。设计文档曾计划16路并行，但实际未实现。

5. **财务数据直接计算，不依赖`fin_ratios`**：所有营收/净利增速通过 `fin_income` 自连接计算，避免使用已知损坏的比率字段。

6. **合同负债存在独立表**：`fin_contract_bs` 由外部脚本从东方财富API抓取，未集成到主财务导入流程中。画像引擎通过 `LEFT JOIN fin_contract_bs` 获取。

## 七、当前局限

1. **批量刷新无并行**：5,500只股票顺序执行，生产环境建议增加多线程/异步并行。
2. **合同负债数据源不稳定**：依赖外部脚本抓取，非标准导入流程。
3. **标签阈值硬编码**：增长率的分类阈值（如25%/50%）写在代码中，不可外部配置。
4. **缺少动态行业基准**：当前所有标签阈值对所有行业一视同仁，未按行业分类调整（如重资产行业的固定资产占比天然高）。
5. **评分规则简单**：`compute_scores` 为简单的加权和规则，未使用机器学习或统计模型。
6. **缺少自动化测试**：画像输出的正确性依赖人工复盘，无法自动化验证。
