> 需求：个股画像页新增「基金持仓变化（基金家数 / 持仓股数）与股价关系图」，数据走预计算（`ads_*` 表），避免前端实时聚合 1235 万行 `fund_portfolio`。

## 一、需求与目标

| 项 | 说明 |
|---|---|
| 展示位置 | 个股画像页「营收·净利润·股价趋势」卡片下方，新增一张卡片 |
| 图内容 | 三组数据随时间（2021Q1–今）变化：①季度末收盘价 + 季内盘中高点；②持仓基金家数；③基金持仓总股数 |

## 二、现状分析

### 2.1 数据表

**`fund_portfolio`**（Tushare Pro 基金持仓，季报披露）：

```sql
ts_code  VARCHAR(12)  -- 基金代码（000001.OF）
ann_date VARCHAR(8)   -- 公告日期（同基金同报告期可有多条，取最新）
end_date VARCHAR(8)   -- 报告期（季度末，20210331…20260630）
symbol   VARCHAR(12)  -- 股票代码（600519.SH）
mkv      DECIMAL(20,4)-- 持有市值(元)
amount   DECIMAL(20,4)-- 持有股数(股)
stk_mkv_ratio, stk_float_ratio
PRIMARY KEY (ts_code, end_date, symbol, ann_date)
```

**关键口径（既有分析已踩坑，必须固化进预计算）：**

1. **披露口径两套**：季报（3/9月，`end_date` 以 03-31/09-30 结尾）仅披露**前十大重仓股**；半年报（06-30）/年报（12-31）披露**全部持仓**。基金数与持股量天然"大小年"交替，**图必须区分口径**（实线=半年报/年报，虚线=季报）。
2. **同基金多公告去重**：同一 `ts_code`+`symbol`+`end_date` 可能有多条 `ann_date`，取最新。
3. **主动/被动基金**：按 `fund_basic.name` 过滤（含 `ETF/指数/沪深300/上证50/中证500/MSCI/增强/联接/LOF/300` 为被动）。
4. **股本/股价**：股本用 `stock_shares_dfcf.total_shares`（禁 `fin_balance_sheet.share_capital`）；股价**不复权**，顶点用**盘中最高**。
5. **送转假象**：近年有"10转X"的股票（如宁德时代2023年10转8），持股量跳升≠加仓，图中需支持按总股本修正说明。

### 2.2 现有接入点

- `compute_ads.py`：`compute()` 全量重建 4 张 ads 表（drop→create→insert→yoy），`POST /api/data/update-ads` 后台调用，进度写 `ads_refresh_log`。
- `profile.py` fin-chart：实时查 `fin_income` + `daily_kline` 聚合，无缓存——新增图若照搬会慢。
- 前端 `renderFinChart()`：纯 Canvas 手绘，多轴（营收/净利/增长率/周K），可复用其坐标缩放与 tooltip 框架。

## 三、预计算表设计

### 3.1 新增表 `ads_stock_fund`（个股×报告期 基金持仓聚合）

```sql
CREATE TABLE ads_stock_fund (
  id INT AUTO_INCREMENT PRIMARY KEY COMMENT '自增ID',
  stock_code  VARCHAR(10)  NOT NULL COMMENT '股票代码(600519)',
  end_date    VARCHAR(8)   NOT NULL COMMENT '报告期(20210331…)',
  quarter     CHAR(6)      COMMENT '季度标签(21Q1…)',
  report_type CHAR(1)      COMMENT '披露口径: F=半年报/年报(全部持仓), Q=季报(前十大)',
  fund_count      INT      COMMENT '持仓基金家数(全部)',
  active_count    INT      COMMENT '主动基金家数',
  passive_count   INT      COMMENT '被动(指数/ETF)基金家数',
  total_amount    DECIMAL(20,4) COMMENT '基金持仓总股数(股)',
  total_mkv       DECIMAL(20,4) COMMENT '基金持仓总市值(元)',
  total_shares    BIGINT   COMMENT '当期总股本(股, 取stock_shares_dfcf, 用于送转识别)',
  close_price     DECIMAL(10,2) COMMENT '季度末收盘价(不复权)',
  intra_high      DECIMAL(10,2) COMMENT '季内盘中最高价(不复权)',
  update_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
                  ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间(插入/更新自动写入)',
  UNIQUE KEY uk_stock_q (stock_code, end_date),
  KEY idx_date (end_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
  COMMENT='个股×季度 基金持仓聚合(基金家数/持股量/市值)+季度股价(预计算, 画像页联动图用)'
```

**行数估算**：~5.5k 股票 × 22 报告期 ≈ **12 万行**，量级与 `ads_stock_annual` 相当，全量重建可接受。

### 3.2 计算逻辑（并入 `compute_ads.py` 新增 Step 5）

对每个报告期 `end_date`：

```sql
-- ① 按基金×股票去重后聚合到"每股每季度"
--    ROW_NUMBER 取同基金同股票最新公告，再 GROUP BY symbol 汇总
INSERT INTO ads_stock_fund (stock_code, end_date, report_type, fund_count, active_count, passive_count, total_amount, total_mkv)
SELECT
  SUBSTRING_INDEX(d.symbol,'.',1) AS stock_code,
  d.end_date,
  CASE WHEN RIGHT(d.end_date,4) IN ('0331','0930') THEN 'Q' ELSE 'F' END,
  COUNT(*),
  SUM(CASE WHEN p.passive=0 THEN 1 ELSE 0 END),
  SUM(p.passive),
  SUM(d.amount), SUM(d.mkv)
FROM (
  SELECT ts_code, symbol, end_date, amount, mkv, ann_date,
         ROW_NUMBER() OVER (PARTITION BY ts_code, symbol, end_date ORDER BY ann_date DESC) rn
  FROM fund_portfolio
) d
JOIN fund_basic f ON f.ts_code = d.ts_code
LEFT JOIN (SELECT ts_code, 1 passive FROM fund_basic
           WHERE name LIKE '%ETF%' OR name LIKE '%指数%' OR name LIKE '%沪深300%'
              OR name LIKE '%上证50%' OR name LIKE '%中证500%' OR name LIKE '%MSCI%'
              OR name LIKE '%增强%' OR name LIKE '%联接%' OR name LIKE '%LOF%' OR name LIKE '%300%') p
  ON p.ts_code = d.ts_code
WHERE d.rn=1
GROUP BY d.symbol, d.end_date
```

然后回填股价与股本（循环每个报告期，或 `daily_kline` 关联子查询）：

- `close_price`：`daily_kline` 中 `trade_date<=end_date` 的最近收盘；
- `intra_high`：`trade_date` 落在上一报告期+1天 ~ 本报告期内的 `MAX(high_price)`；
- `total_shares`：`stock_shares_dfcf.total_shares`（一次拉全量 map 复用既有 `_shares_map()`）。

> 性能：`fund_portfolio` 1235万行全表 JOIN 一次约 30–60s，可接受（与 Step3 全表扫 `daily_kline` 同级）。若想提速，可对 `fund_portfolio` 增加 `(symbol)` 前缀索引（已有 `idx_symbol`，足够）。

## 四、后端 API 设计

**方案：扩展 `GET /api/profile/{code}/fin-chart`**，新增字段 `fund_series`（避免新起 endpoint，一次拉全两张图）：

```json
{
  "years": [...], "revenues": [...], "profits": [...],
  "growth_rates": [...], "weekly_kline": [...],
  "fund_series": {
    "labels":   ["21Q1","21Q2",..."26Q2"],
    "report_type": ["Q","F",...],
    "close_price":  [9.62, ...],
    "intra_high":   [15.00, ...],
    "fund_count":   [397, 900, ...],
    "active_count": [355, 666, ...],
    "total_amount": [29.62, 33.56, ...],   // 亿股
    "total_mkv":    [285, 325, ...],        // 亿元
    "has_split":    false                    // 近年是否有送转(10转X)
  }
}
```

**查询**（画像页秒开）：

```sql
SELECT quarter, report_type, close_price, intra_high,
       fund_count, active_count,
       ROUND(total_amount/1e8,2) total_amount, ROUND(total_mkv/1e8,0) total_mkv
FROM ads_stock_fund
WHERE stock_code = %s
ORDER BY end_date
```

`has_split`：由预计算时检测（近5年分红送转接口含"10转X"则 true），前端据此在图上注记"⚠送转后持股量跳升非加仓"。

**现有 fin-chart 接口不预计算、实时查原始表**——本次新增的 `fund_series` 全部读 `ads_stock_fund`（命中需求"预计算"），其余字段保持不动。

## 七、风险与注意事项

| 风险 | 对策 |
|---|---|
| `fund_portfolio` 1235万行全量 JOIN 较慢 | 预计算一次性完成，页面零开销；必要时优化为按 `symbol` 分批 |
| 季报/半年报口径差异误读 | 图表区分实线/虚线 + 图例说明；对比只用同口径 |
| 送转放大持股量 | `total_shares` 冗余入库 + `has_split` 注记 |
| 2026H1 半年报披露约60%，最新一期偏低 | 数据管理页显示披露进度；图可标注"最新期披露中" |
| 回测/筛选等其他页面误用本表 | `ads_stock_fund` 仅服务画像联动图，不加入筛选查询 |
