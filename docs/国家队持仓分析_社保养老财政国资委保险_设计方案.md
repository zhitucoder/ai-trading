# 国家队持仓分析 — 设计方案（社保 / 养老 / 财政部 · 国资委 / 保险 / 北向·香港中央结算）

> 基于 `top10_float_holders`（个股前十大流通股东）与 `daily_kline`、`stocks`、`stock_sectors`、`ads_stock_latest`
>
> 目标：提供一套**可复用的「机构主体持仓分析」框架**，先落地「社保基金」，再一键扩展到基本养老保险、财政部系（国开金融）、国资委系（国新宏盛）、保险系、以及**北向通道「香港中央结算」**等任意机构主体。

---

## 一、解决的问题

`top10_float_holders` 表已包含 51 万条记录、67,779 个股东名、覆盖 10 个季度（2024Q1 ~ 2026Q2）、5,208 只股票。用户关心三类问题：

1. **某类机构当前持仓全貌**：持仓市值大小、占公司股份比例、行业偏好。→ 社保、养老、保险、财政部、国资委、北向（香港中央结算）
2. **持仓变化**：最近一个季度增持/减持/新开仓了哪些股票、哪些板块。
3. **多类机构对比 / 交叉**：哪些公司同时被社保、国资委、养老金、保险持有（「国家队共持」）。

### 关键洞察（已核实的数据现实）

| 维度 | 数据现状 |
|------|---------|
| 股东识别 | `holder_name`（如「全国社保基金一零一组合」「国开金融有限责任公司」「中国人寿保险-传统-普通保险产品」）+ `holder_type`（如「社保基金、社保机构」「基本养老保险基金」「保险投资组合」「国资局」「一般企业」） |
| 季度 | `end_date` 20240331 ~ 20260630，共 10 个季度 |
| 股本覆盖 | 社保系 ~67 个股东名、养老系 ~100 个、保险系 ~177 个、北向（香港中央结算）覆盖 2,000~3,400 只股票 |
| 名字差异 | **必须用正则而非精确匹配**（见 §2.2）：如「全国社保一一零组合」「全国社保基金一一零组合」「中信证券-社保基金1106组合」三体并存 |
| 互联键 | `ts_code` = `XXXXXX.SZ/SH`，需 `SUBSTRING_INDEX(ts_code,'.',1)` 转 `stocks.stock_code` / `daily_kline.stock_code` |

## 二、机构主体识别（核心设计）

### 2.1 双通道识别：`holder_type`（可扩展）+ `holder_name` 正则（当前）

`holder_type` 字段已存在，适合**集团类粗分类**；但未来要精确区分「财政部系」「国资委系」下的具体公司（国开金融 vs 国新宏盛），必须用「**机构主体白名单 + 名称正则**」。

### 2.2 机构别名归一化（必读，数据库里没有规范名）

同名机构在 `holder_name` 里有多种写法，**精确匹配会漏数据**。需要维护一个归一化字典（正则替换后再归类）：

| 类别 | 识别规则（正则） | 归一化后主体名 |
|------|-----------------|---------------|
| **社保基金** | 含「社保基金」或「全国社保」或 `社保基金\d+组合` | `社保基金` |
| **基本养老保险** | 含「基本养老保险基金」 | `基本养老保险基金` |
| **养老金产品** | 含「养老金产品」（区别于基本养老保险） | `养老金产品`（可单独成类） |
| **保险（寿险/财险/集团）** | `holder_type in (保险投资组合, 金融机构-保险公司, 保险资管产品, 保险公司)` 或名称含「保险」 | 先按 `holder_type`，再按「公司名」细分 |
| **财政部系** | 名称 ∈ 白名单：`国开金融有限责任公司`、`中华人民共和国财政部` 等 | 归属「财政部实控」 |
| **国资委系** | 名称 ∈ 白名单：`国新宏盛投资(北京)有限公司`、`国新控股`、`国新投资` 等 | 归属「国务院国资委实控」 |
| **北向/香港中央结算** | 名称含 「香港中央结算」 或 `HKSCC` | 归属「北向通道」（`hk_central`） |

> ⚠️ **保险与养老的坑**：许多「养老金产品」（如「中信证券信养天年股票型养老金产品」）是保险系发行的，别混进「基本养老保险基金」。**基本养老保险**严格匹配「基本养老保险基金」六个字。**保险**优先用 `holder_type`（`保险投资组合` 等）而不是名字里的「保险」二字（会误伤「国信保险」「太平保险」等公司全称里的字）。
>
> ⚠️ **北向（香港中央结算）的特殊性**：这是**沪股通/深股通（陆股通）资金汇总持仓的托管通道**，不是单一机构。其 `holder_type` 多为「一般企业」，**覆盖全市场 2,000~3,400 只股票**（是全市场最大的"股东"），与社保/国开等"真·国家队"的持股逻辑完全不同——它代表**北向外资/借道资金**的整体动向，而非某个实体的意图。分析时应**单列成类**，且注意：
> - 涨停板名称大量变体（见 §2.3），必须归一化合并，否则同一季度同一股票会被拆成多行重复计算。
> - 口径上是「全部北向合计」，无法拆出具体外资机构；如需细拆，另需北向个股持股明细接口（当前表无此数据）。
> - 其「增持/减持」变化受**股价波动 + 真金白银买卖**双重影响，市值口径需明确说明。

建议新建配置表（可后续做前端可维护）：

```sql
-- 机构主体 → 归属势力（财政部/国资委/社保/保险/养老/北向…）
CREATE TABLE holder_owner (
  id INT AUTO_INCREMENT PRIMARY KEY,
  pattern      VARCHAR(255) NOT NULL,   -- 名称正则/关键词
  match_type   ENUM('regex','exact','substr') DEFAULT 'substr',
  group_name   VARCHAR(50) NOT NULL,    -- 归一化主体名，如「全国社保基金」「香港中央结算」
  owner_type   VARCHAR(32) NOT NULL,    -- 归属势力：shebao/yanglao/caizheng/guozwei/baoxian/hk_central
  owner_label  VARCHAR(50) NOT NULL,    -- 展示名：社保基金/基本养老保险/财政部/国资委/保险/北向·香港中央结算
  priority     INT DEFAULT 0,           -- 冲突时谁优先
  remark       VARCHAR(255)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.3 香港中央结算名称变体（已核实，必须合并）

全市场北向资金散落成 **18 种写法**，同一股票同一季度会被拆成多行。归一化时**统一合并**为 `香港中央结算`：

| 归一化前变体 | 记录数 | 覆盖股票 |
|-------------|-------|---------|
| 香港中央结算有限公司 | 23,318 | 3,427 |
| HKSCCNOMINEESLIMITED | 727 | 106 |
| 香港中央结算(代理人)有限公司 | 683 | 73 |
| 香港中央结算代理人有限公司 | 43 | 6 |
| 香港中央结算有限公司(A股 / H股 / 沪股通) | 各≤26 | 各≤3 |
| HKSCCNomineesLimited(香港中央结算(代理人)有限公司) | 23 | 5 |
| …其余约 10 种变体 | 各≤20 | 各≤5 |

> 归一化规则：`正则剔除括号后缀（(代理人) / (A股) / (H股) / (沪股通) / 数字尾缀）→ 统一匹配「香港中央结算」前缀或首个 HKSCC`。注意**排除**「中国农业银行-中证500ETF…香港中央结算有限公司」这种托管行基金字样（罕见，需去重兜底）。

## 三、需要分析哪些数据（分析维度）

### 3.1 持仓市值缺口与补法（关键）

`top10_float_holders` 只给 **股数**（`hold_amount`）和 **占流通/总股本比例**（`hold_ratio` / `hold_float_ratio`），**没有持仓市值**。需要补：

```
持仓市值(元) = hold_amount(股) × 当季末收盘价
```

季末价来源：`daily_kline` 中 `trade_date` 与该季度 `end_date` 最接近（≤ 该日）的 `close_price`。**避免用当前价**（跨季度市值对比会失真）。

### 3.2 分析维度清单

| 维度 | 指标 | 数据来源 |
|------|------|---------|
| **持股全景** | 持公司数、总持仓市值、各组合持仓脱敏、平均持股比例 | - |
| **市值规模** | 单公司持仓市值、持仓市值 TopN | `hold_amount × 季末价` |
| **股权占比** | 占流通/总股本比例（`hold_float_ratio`/`hold_ratio`）、是否进入前十大 | 直取 |
| **行业偏好** | 持仓市值按行业（industry）板块聚合 | `stock_sectors` |
| **概念偏好** | 按概念（concept）板块聚合，看风格 | `stock_sectors` |
| **持仓变化** | 季环比：增持/减持/新开仓/清仓（股数与市值双口径） | `hold_change` + 前后季度对比 |
| **板块轮动** | 增持/减持股票聚焦的行业变动，本季新进入哪些板块 | - |
| **交叉持股** | 多类「国家队」共持的公司（社保∩养老∩国资委…） | §6 |
| **风格画像** | 机构持仓组合的市值、PE、ROE、股息率分布 | `ads_stock_latest` |

## 四、预计算表设计（ads_ 前缀，一次性计算）

沿用仓库现有 `ads_*` + `compute_*.py` 约定（同 `compute_fund_ads.py` 模式）。核心是一张**机构×股票×季度**的聚合表 + 若干派生视图。

### 4.1 ads_institution_stock — 机构主体逐股持仓

```sql
CREATE TABLE ads_institution_stock (
  id INT AUTO_INCREMENT PRIMARY KEY,
  owner_type   VARCHAR(32) NOT NULL,     -- shebao/yanglao/caizheng/guozwei/baoxian
  group_name   VARCHAR(50) NOT NULL,     -- 归一化主体，如「全国社保基金」
  stock_code   VARCHAR(10) NOT NULL,
  stock_name   VARCHAR(50),
  end_date     VARCHAR(8) NOT NULL,
  quarter      CHAR(6),                  -- 26Q2
  -- 持仓（按该机构全部组合在该股上的汇总）
  holder_cnt   INT,                      -- 该机构下多少组合/产品持有此股
  total_hold   DECIMAL(20,4),            -- 合计持股股数
  hold_ratio   DECIMAL(10,4),            -- 合计占总股本比例(%)
  hold_float_ratio DECIMAL(10,4),        -- 合计占流通比例(%)
  close_price  DECIMAL(10,2),            -- 当季末收盘价
  hold_mkv     DECIMAL(20,2),            -- 持仓市值=total_hold×close_price
  update_time  DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk (owner_type, group_name, stock_code, end_date),
  KEY idx_date (end_date),
  KEY idx_mkv (hold_mkv)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**数据量**：非自然人机构前十大股东中，社保+养老+保险+财政+国资系合计约几千只股票 × 10 季度 ≈ 数十万行级；**加入北向（香港中央结算，覆盖 2,000~3,400 只股票）后将显著增大**（预计整体 ≤ 100 万行，以白名单过滤后为准）。

### 4.2 ads_institution_change — 个股季环比（变化分析核心）

在 4.1 基础上做相邻季度对比，得到每只股票每个季度的增减数据：

```sql
CREATE TABLE ads_institution_change (
  id INT AUTO_INCREMENT PRIMARY KEY,
  owner_type   VARCHAR(32) NOT NULL,
  group_name   VARCHAR(50) NOT NULL,
  stock_code   VARCHAR(10) NOT NULL,
  stock_name   VARCHAR(50),
  end_date     VARCHAR(8) NOT NULL,
  prev_end_date VARCHAR(8) NOT NULL,
  quarter      CHAR(6),
  hold_mkv     DECIMAL(20,2),           -- 本季持仓市值
  prev_hold_mkv DECIMAL(20,2),          -- 上季持仓市值
  mkv_change   DECIMAL(20,2),           -- 市值变化(受股价+数量双重影响)
  total_hold   DECIMAL(20,4),
  prev_total_hold DECIMAL(20,4),
  hold_change  DECIMAL(20,4),           -- 股数变化
  hold_change_pct DECIMAL(10,2),        -- 股数变化率(%)
  action       ENUM('新开仓','增持','减持','清仓','持有') ,
  update_time  DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk (owner_type, group_name, stock_code, end_date),
  KEY idx_action (action),
  KEY idx_date (end_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**action 判定规则**：
```
上季度无持仓 且 本季有   → 新开仓
上季有 且 本季股数 > 上季 → 增持
上季有 且 本季股数 < 上季 → 减持
上季有 且 本季无         → 清仓
否则                      → 持有
```

### 4.3 ads_institution_sector — 板块级（行业/概念）持仓流向

```sql
CREATE TABLE ads_institution_sector (
  id INT AUTO_INCREMENT PRIMARY KEY,
  owner_type  VARCHAR(32) NOT NULL,
  group_name  VARCHAR(50) NOT NULL,
  sector_type VARCHAR(20) NOT NULL,    -- industry/concept
  sector_name VARCHAR(50) NOT NULL,
  end_date    VARCHAR(8) NOT NULL,
  stock_cnt   INT,                     -- 该板块内被持股票数
  hold_mkv    DECIMAL(20,2),           -- 该板块总持仓市值
  prev_hold_mkv DECIMAL(20,2),
  mkv_change  DECIMAL(20,2),
  mkv_change_pct DECIMAL(10,2),
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk (owner_type, group_name, sector_type, sector_name, end_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.4 ads_institution_overview — 机构主体季度总览（指标卡片）

```sql
CREATE TABLE ads_institution_overview (
  id INT AUTO_INCREMENT PRIMARY KEY,
  owner_type VARCHAR(32) NOT NULL,
  group_name VARCHAR(50) NOT NULL,
  end_date   VARCHAR(8) NOT NULL,
  quarter    CHAR(6),
  stock_cnt  INT,                    -- 持股公司数
  holder_cnt INT,                    -- 组合/产品数
  total_mkv  DECIMAL(20,2),          -- 总持仓市值
  avg_ratio  DECIMAL(10,4),          -- 平均持股比例
  top_stock  VARCHAR(50),            -- 本季最大持仓
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk (owner_type, group_name, end_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 五、数据流与计算脚本

### 5.1 DFD

```
top10_float_holders      daily_kline(季末价)      stocks / stock_sectors / ads_stock_latest
        │                       │                        │
        └──────────┬────────────┴────────────────────────┘
                   ▼
     机构白名单归一化(holder_owner 表 + 正则)
                   ▼
   ┌────────────────────────────────────────────┐
   │ src/compute_institution_ads.py             │
   │  1. 归属识别(归一化 group_name/owner_type)  │
   │  2. 拼季末价 → 算持仓市值                   │
   │  3. 写 ads_institution_stock                │
   │  4. 相邻季度对比 → ads_institution_change   │
   │  5. 板块聚合 → ads_institution_sector       │
   │  6. 季度汇总 → ads_institution_overview     │
   └────────────────────────────────────────────┘
                   ▼
   API + 前端（社保/养老/财政/国资委/保险 复用）
```

### 5.2 季末价获取 SQL（示例）

```sql
-- 某季度某股票的季末收盘价（取 ≤ end_date 的最近交易日）
SELECT k.close_price
FROM daily_kline k
WHERE k.stock_code='600463' AND k.trade_date <= '20260630'
ORDER BY k.trade_date DESC LIMIT 1;
```

### 5.3 更新频率
- `top10_float_holders` 每季度新增后运行一次 `compute_institution_ads.py`
- 白名单（`holder_owner`）新增机构主体时，只重算受影响 owner_type

## 七、具体案例（SQL 验证）

### 案例1：社保基金 26Q2 持仓市值 Top（需拼季末价）

```sql
SELECT s.stock_code, s.stock_name, s.hold_mkv, s.hold_float_ratio
FROM ads_institution_stock s
WHERE s.owner_type='shebao' AND s.end_date='20260630'
ORDER BY s.hold_mkv DESC LIMIT 20;
```

### 案例2：社保基金 26Q2 新开仓

```sql
SELECT c.stock_code, c.stock_name, c.hold_mkv
FROM ads_institution_change c
WHERE c.owner_type='shebao' AND c.end_date='20260630' AND c.action='新开仓'
ORDER BY c.hold_mkv DESC LIMIT 30;
```

### 案例3：财政部系（国开金融）板块偏好

```sql
SELECT sector_name, hold_mkv, mkv_change
FROM ads_institution_sector
WHERE owner_type='caizheng' AND group_name='国开金融' AND end_date='20260630'
  AND sector_type='industry'
ORDER BY hold_mkv DESC LIMIT 20;
```

### 案例4：多主体共持（社保 ∩ 养老 ∩ 保险）

```sql
SELECT stock_code, stock_name, count(DISTINCT owner_type) as owner_cnt,
       group_concat(DISTINCT owner_type) as owners
FROM ads_institution_stock
WHERE end_date='20260630' AND owner_type IN ('shebao','yanglao','baoxian','caizheng','guozwei')
GROUP BY stock_code, stock_name
HAVING count(DISTINCT owner_type) >= 3
ORDER BY owner_cnt DESC;
```

### 案例5：北向（香港中央结算）26Q2 增持 Top（归一层后）

> ⚠️ 必须先归一化（§2.3）再聚合，否则 18 种变体会把同一股票拆成多行、增持算错。`compute_institution_ads.py` 在写入 `ads_institution_stock` 时已把全部变体合并为 `group_name='香港中央结算'`，故此处直接查聚合表即可：

```sql
SELECT c.stock_code, c.stock_name, c.mkv_change, c.hold_change_pct
FROM ads_institution_change c
WHERE c.owner_type='hk_central' AND c.end_date='20260630'
  AND c.action IN ('增持','新开仓')
ORDER BY c.mkv_change DESC LIMIT 30;
```

## 十、后续可补充的数据（进阶）

当基础框架跑通后，可增量补充：

1. **持股成本 / 浮盈**：以建仓季均价为成本，对比现价算浮盈浮亏（需 `daily_kline` 区间均价）。
2. **个股仓位集中度**：机构单个组合占其全部持仓比例，判断重点押注。
3. **新进组合 TOP 榜**：具体哪几个社保组合（如 101 组合）本季加仓最多。
4. **持股周期分析**：连续持有几个季度、是否长线（社保以长线著称）。
5. **机构画像标签**：该机构偏好市值段 / 行业 / 风格（价值/成长）的自动画像，写入画像系统。
6. **机构行为日历**：结合财报披露时间，提示哪些组合即将有新动作。
7. **与基金持仓联动**：对接 `ads_fund_*`，看「国家队」与公募资金是否同向。
