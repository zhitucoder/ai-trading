# 个股画像 —— 公司介绍与定位变化展示（设计文档）

> 版本：v1.0 | 日期：2026年8月
> 关联代码：`src/app/routers/profile.py`、`src/app/strategies/profile.py`、`web/index.html`、`web/app.js`

---

## 一、背景与目标

### 1.1 需求

个股画像页当前只展示量化数据（阶段、评分、标签、财务指标），缺少"这家公司是干什么的、现在变成什么了"的**一句话认知**。需求：

1. 为每家公司生成一段 **约100字** 的公司介绍
2. 明确标出 **公司定位是否发生变化**（如"安防 → 智能物联+AIoT"）
3. 显示位置在 **个股画像页面上方**（页头下方、图表上方）

### 1.2 目标效果（示例）

> **海康威视**（002415）
> 曾经的安防之王，正转型为"智能物联+AIoT"龙头。以视频监控起家，现业务横跨智能物联、机器视觉与汽车电子，AI大模型与渠道网络构成核心壁垒。
> 定位标签：**转型中** ｜ 安防 → 智能物联 + AIoT

- 介绍文案 100字左右，读一遍即可建立对公司的整体认知
- 定位变化一目了然：未变 / 转型中 / 跨界延伸 / 第二曲线 等
- 数据缺失时页面优雅降级（不显示该卡片）

### 1.3 设计原则

1. **介绍是"定性内容"，不走量化实时计算**：公司定位变化由 AI 预生成 + 人工审校维护，避免每次画像实时生成（5000+ 只股票不可行）
2. **与画像缓存解耦**：`stock_profiles.profile_json` 每天批量刷新，而公司介绍低频变化。介绍存独立表，路由层合并进 `/api/profile` 响应，避免批量刷新覆盖或牵连
3. **有兜底**：无介绍数据的股票不报错、不显示空卡片，保持现有画像页可用
4. **可追溯**：记录来源（AI/人工）与更新时间，支持后续人工修正覆盖

## 二、功能设计

### 2.1 信息结构

每只股票一条介绍记录，包含三部分：

| 字段 | 说明 | 示例 |
|:---|:---|:---|
| **介绍文案** | 约100字的一段话 | 海康威视上文示例 |
| **定位状态** | 定位是否发生变化（枚举） | `transforming`（转型中） |
| **定位标签** | "过去 → 现在"的精简概括 | 安防 → 智能物联 + AIoT |

定位状态枚举定义：

| 枚举值 | 中文 | 含义 | 例句风格 |
|:---|:---|:---|:---|
| `unchanged` | 定位未变 | 主业与市场认知一致 | "XX领域龙头企业，深耕主业二十余年" |
| `transforming` | 转型中 | 从旧主业转向新方向，过渡期 | "曾经的安防之王，正转型为…" |
| `diversifying` | 跨界延伸 | 在主业之外延伸新业务线 | "以XX为主业，积极布局XX第二曲线" |
| `pivoting` | 战略转向 | 明确调转船头，新方向为主导 | "由XX全面转向XX，新业务已占营收大头" |
| `unknown` | 未知 | 无介绍数据 / 无法判定 | — |

> 前端只需对前四种渲染彩色徽章；`unknown` 时不显示徽章或显示灰色"定位待补充"。

## 三、数据模型设计

### 3.1 新表：`stock_intro`

```sql
CREATE TABLE stock_intro (
    stock_code        VARCHAR(10)  NOT NULL,
    stock_name        VARCHAR(50)  DEFAULT NULL,          -- 冗余名称，便于管理端检索
    intro             VARCHAR(500) NOT NULL DEFAULT '',   -- 约100字介绍（UTF-8 中文每字3字节）
    positioning_status VARCHAR(20) NOT NULL DEFAULT 'unknown',
        -- unchanged / transforming / diversifying / pivoting / unknown
    positioning_label  VARCHAR(100) DEFAULT NULL,          -- "安防 → 智能物联 + AIoT"
    source            VARCHAR(20)  NOT NULL DEFAULT 'ai',
        -- ai / manual / template
    updated_at        DATETIME DEFAULT CURRENT_TIMESTAMP
                       ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (stock_code),
    KEY idx_status (positioning_status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**设计要点：**

- **不落 `profile_json`**：介绍是低频静态内容，独立成表，批量画像刷新（`profile_batch.py` 每天刷 5500 只）不受影响
- 无历史版本需求，故不建历史表；如后续需要，可加 `version` 列或审计表
- 介绍文案限 `VARCHAR(500)`：100 汉字 ≈ 300 字节（utf8mb4），500 字节留出标点与回退余地

## 四、生成策略

### 4.1 三层生成管线（质量递增）

```
第1层 模板兜底  →  第2层 AI 批量生成  →  第3层 人工精修核心标的
（离线，全覆盖）   （离线脚本，批量）     （管理端/手动SQL）
```

| 层级 | 方式 | 覆盖范围 | 质量 | 触发时机 |
|:---|:---|:---|:---|:---|
| **模板兜底** | 规则模板：用现有画像数据拼句 | 全部 5500+ | 一般 | 数据入库时自动 |
| **AI 生成** | LLM 批量脚本，喂财务+行业+概念摘要 | 全部或重点池 | 较好 | 手动/定时运行 |
| **人工精修** | 人工撰写/修正 | 龙头股、自选、持仓 | 最优 | 随时，覆盖 AI 结果 |

> **生产建议**：模板兜底保证"人人有介绍"；AI 生成保证覆盖完整；对核心标的（如自选股、持仓）人工精修，`source='manual'` 永不被自动脚本覆盖。

### 4.2 模板兜底（`strategies/stock_intro.py`）

输入为现有画像数据（`generate_profile` 输出即可），无需新数据源。拼接规则示例：

```
[行业]领域[地位词]，[近况句]。[定位句]
例：光模块龙头，营收同比+60%，净利+116%，为AI算力核心受益标的。
```

- **行业**：`sectors.industry[0]`
- **地位词**：按规模/增速推断（"龙头"/"领先"/"布局者"）
- **近况句**：`fin_data.revenue_growth_rate`、`net_profit_growth_rate`、`gross_margin`、`debt_ratio`
- **定位句**：按定位状态取固定句式（见 2.1 例句风格）
- 超长裁剪到 100 字左右

### 4.3 AI 批量生成（`src/generate_stock_intro.py`）

离线脚本，逐只构造 Prompt 调用 LLM（OpenAI 兼容接口，可配置 base_url / key / model）：

**Prompt 输入**（全部来自本地可信数据，不用外部联网）：
- 股票代码、名称、行业/概念/风格板块
- 最近一年营收、净利、同比增速、毛利率、负债率
- 近5年营收 CAGR、近 3~5 年营收序列（用于识别结构变化，如营收加速/下滑/换挡）
- 现有 `biz_tags` / `ind_tags`（如"十倍股"、"营收爆发增长"）

**Prompt 输出约束**：
- 严格 100 字左右（80~120 字）
- 必须包含"过去是什么 → 现在是什么"的定位变化判断（无法判断则写现状）
- 输出 JSON：`{"intro": "...", "positioning_status": "...", "positioning_label": "..."}`
- 失败重试 2 次，仍失败则回退模板兜底

**写入策略**：`source='ai'` 的记录可被覆盖；`source='manual'` 跳过。

## 五、API 设计

### 5.1 扩展 `GET /api/profile/{stock_code}` 响应

在 `routers/profile.py` 的 `get_profile()` 中合并介绍（缓存路径与实时路径都合并）：

```python
def get_profile(stock_code: str, refresh: bool = False):
    if not refresh:
        # ... 现有缓存读取，得到 data ...
    else:
        data = generate_profile(stock_code)
    data['intro'] = get_stock_intro(stock_code)   # 新增：查 stock_intro 表
    return data
```

响应新增字段：

```json
{
    "code": "002415",
    "name": "海康威视",
    "...": "其余字段不变",
    "intro": {
        "text": "曾经的安防之王，正转型为\"智能物联+AIoT\"龙头。以视频监控起家，现业务横跨智能物联、机器视觉与汽车电子，AI大模型与渠道网络构成核心壁垒。",
        "positioning_status": "transforming",
        "positioning_label": "安防 → 智能物联 + AIoT",
        "source": "ai",
        "updated_at": "2026-08-01 10:00:00"
    }
}
```

**兼容性**：无介绍记录时返回 `"intro": null`，前端据此隐藏卡片，不影响现有字段与调用方。

### 5.2 （可选，v1.1）人工维护接口

```http
POST /api/profile/{stock_code}/intro
Body: { "text": "...", "positioning_status": "transforming", "positioning_label": "..." }
```
- 写入 `source='manual'`，供管理端/后台人工修正
- 鉴权沿用现有无鉴权体系，仅内网使用

### 5.3 不新增独立读接口

介绍随 `/api/profile` 一起返回，避免前端多一次往返；也无需改动 `/api/profiles/search`（介绍字段不做筛选维度）。

## 六、前端展示设计

### 6.1 位置

`web/index.html` 单股画像模板中，**位于 `.profile-header` 之后、财务趋势卡片之前**：

```
<div class="profile-header"> … 代码/名称/价格/自选 … </div>
↓ 新增
<div class="card intro-card" v-if="profile.intro">   ← 公司介绍卡片
     <div class="intro-badge">转型中</div>
     <p class="intro-text">曾经的安防之王，正转型为…</p>
     <div class="intro-meta">定位标签 · 更新于 …</div>
</div>
↓
<div class="card"> 营收·净利润·净利增长率·股价趋势 </div>
```

### 6.2 视觉样式（沿用深色科技风）

- 卡片背景：半透明 `rgba(255,255,255,0.03)`，左侧金色竖条（`#e2b714`）点缀，与评分/阶段卡片一致
- 徽章配色按定位状态区分：
  - 转型中 `transforming` → 金色 `#e2b714`
  - 跨界延伸 `diversifying` → 青色 `#00d4ff`
  - 战略转向 `pivoting` → 紫色
  - 定位未变 `unchanged` → 绿色 `#22c55e`
  - 未知 → 灰色
- 介绍正文：14px，行高 1.7，浅色 `#ccc`
- 定位标签与更新时间：12px 弱化灰

### 6.3 降级策略

- `profile.intro` 为 `null` 或 `text` 为空 → 整个卡片不渲染
- `positioning_status === 'unknown'` → 不渲染徽章，仅显示正文
- 不引入新的构建/依赖，纯 Vue 模板 + 既有 CSS 类

## 八、风险与注意事项

1. **AI 生成幻觉**：LLM 可能编造营收结构/业务占比。Prompt 只喂可信本地数据，输出仅限结构化 JSON；核心标的走人工精修
2. **金融股数据可靠性**：金融企业财报字段映射有历史问题，模板/AI 输入需沿用 `rev_reliable()` 校验，脏数据公司回退"定位待补充"
3. **批量刷新不覆盖**：介绍独立成表，`profile_batch.py` 每日刷新 `stock_profiles` 时**不要**触碰 `stock_intro`
4. **100字约束**：生成端裁剪 + `VARCHAR(500)` 兜底，超长截断不报错
5. **命名冲突**：`profile.intro` 为新增顶层键，需确认前端模板/`profile_batch.py` 无同名字段使用（当前无）
6. **更新频率**：定位变化低频，按季度或重大公告触发 AI 重生成即可，不必随每日画像刷新
