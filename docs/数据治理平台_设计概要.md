# 数据治理平台 — 设计概要

> 版本：v0.1（设计评审稿）｜日期：2026-08-11
> 范围：数据资产目录（元数据管理）+ 数据血缘可视化（表级/字段级）
> 状态：待评审

---

## 1. 背景与目标

当前系统已积累 32 张数据表（行情、财务、板块、股本、分红、预计算分析、日志等），但存在三个治理盲区：

1. **元数据散乱**：`ads_*` 等 10+ 张表没有表注释/列注释，数据来源、最新数据日期散落在各 import/compute 脚本中，没有统一视图。
2. **血缘不可见**：`ads_stock_latest` 由 6 张源表在 Python 侧合并生成，`ads_sector_*` 存在两级聚合（`fin_*` → `ads_stock_*` → `ads_sector_*`），但没有任何地方展示"这张表/字段从哪来"。
3. **查找困难**：只能靠 `mysql` 命令行或读代码，无法按中文名/英文名前缀检索表。

### 目标

| # | 目标 | 验收标准 |
|---|---|---|
| 1 | 数据资产可视化、归类、查看 | 一个页面列出全部 32 张表：英文表名、中文表名、业务分类、数据来源、行数、**最新数据日期** |
| 2 | 表名智能搜索提示 | 输入前缀（英文/中文）即提示表全名 + 中文名，支持模糊搜索 |
| 3 | 表级血缘可视化 | 点开任意表，展示其上游来源表与下游消费表（DAG 图） |
| 4 | 字段级血缘可视化 | 点开字段，展示该字段由哪些源表字段通过什么公式生成，**显示字段名与注释** |

### 2.2 已有可复用的元数据信号

- **source 列**：`stock_shares_dfcf.source`、`stock_shares.source`、`stock_dividend.source`、`fin_contract_bs.source`、`stock_intro.source` —— 可直接作为"数据来源"字段。
- **刷新日志**：`ads_refresh_log`（status/total/computed/started_at/finished_at）—— 已有现成的预计算任务追踪。
- **新鲜度探测模式**：`data_management.py` 已用 `MAX(trade_date)` / `MAX(report_date)` / `MAX(started_at)` 探测各表最新日期，直接复用。
- **全库列注释**：`information_schema.columns.column_comment` 已有 fin_*/kline/板块/股本等表的中文列注释；**ads_* 系列列注释为空是最大缺口**。

### 2.3 关键发现

1. `ads_stock_latest` 是 **Python 侧合并**（非单条 SQL），血缘来源跨 6 张表：`fin_income`（最新报告期+TTM+同比）、`ads_stock_annual`（年报指标）、`daily_kline`（最新价）、`stock_shares_dfcf`（股本）、`stock_dividend`（股息率）、`stocks`（名称）。
2. `ads_sector_*` 是两级聚合：`fin_* → ads_stock_annual → ads_sector_annual`，血缘应记录为"多跳"。
3. 已知问题：`compute_ads.py:426` 的 `roe_ttm` 实际等于 `roe`（未做 TTM 计算）——血缘文档中需如实标注。
4. 系统中 **没有任何已有的血缘/目录代码**（全绿地），无 information_schema 读取先例。

## 3. 总体架构

```
┌─────────────────────────── 前端（web/，Vue3 CDN SPA）───────────────────────────┐
│  页面一：数据资产目录（data-catalog-page）   页面二：数据血缘（data-lineage-page）│
│  搜索提示 / 分类筛选 / 表清单 / 列详情        表级DAG图 / 字段级血缘 / 字段注释    │
└──────────────────────────────────────────────────────────────────────────────┘
                                    │  fetch /api/governance/*
┌─────────────────────────── API 层（FastAPI）───────────────────────────────────┐
│  src/app/routers/governance.py  （prefix=/api/governance, tags=['数据治理']）    │
│  ├─ 资产查询  GET /tables  GET /tables/suggest  GET /tables/{t}  GET /tables/{t}/columns
│  ├─ 血缘查询  GET /lineage/table/{t}  GET /lineage/field/{t}/{col}
│  └─ 元数据    POST /meta/{t}（编辑中文名/分类/来源说明）  POST /refresh（刷新统计）
└──────────────────────────────────────────────────────────────────────────────┘
                                    │  database.py (query/execute, DictCursor)
┌─────────────────────────── 数据层（MySQL ai_trading）──────────────────────────┐
│  动态元数据：information_schema + MAX(date_col) 探测（不落库，实时）              │
│  静态元数据：data_catalog_meta（表级：中文名/分类/来源/说明）                     │
│  血缘元数据：data_lineage（表级边 + 字段级边 + 转换公式）                         │
│  血缘配置源：config/lineage.yaml（人工整理，初始化脚本灌入）                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

**设计原则**：
- **动态与静态分离**：表清单/列注释/行数/最新日期来自 `information_schema` + `MAX()` 实时查询，永远真实；中文名/业务分类/来源说明这些"人写的元数据"落库可编辑。
- **血缘声明式管理**：字段级血缘由 `config/lineage.yaml` 声明（依据 compute_ads.py 的映射整理），用初始化脚本灌入 `data_lineage` 表，避免脆弱的 SQL 静态解析。
- **无新增第三方后端依赖**：全部用现有 `database.py` 帮助函数。

## 4. 数据资产目录设计

### 4.1 元数据表：`data_catalog_meta`

```sql
CREATE TABLE IF NOT EXISTS data_catalog_meta (
  table_name      VARCHAR(64)  NOT NULL COMMENT '英文表名',
  table_comment   VARCHAR(255) NOT NULL DEFAULT '' COMMENT '中文表名（目录展示名）',
  category        VARCHAR(32)  NOT NULL DEFAULT '' COMMENT '业务分类：行情/财务/板块/股本/分红/预计算/用户内容/日志',
  source          VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '数据来源：通达信/东方财富/系统计算/AI生成/人工',
  refresh_method  VARCHAR(128) NOT NULL DEFAULT '' COMMENT '刷新方式：import_kline.py / compute_ads.py / 运行期写入',
  latest_date_col VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '新鲜度探测列：trade_date/report_date/updated_at/started_at',
  description     VARCHAR(512) NOT NULL DEFAULT '' COMMENT '补充说明（口径、已知问题等）',
  PRIMARY KEY (table_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据资产目录-表级元数据（人工维护）';
```

- 初始化脚本 `src/init_governance.py` 一次性灌入 32 张表的种子数据（重点补齐 `ads_*` 缺失的中文名/列注释说明）。
- 分类体系（5 大域 32 表）：**行情**（3）｜**财务**（9）｜**板块与股本**（4）｜**预计算分析**（9：4 张 ads_* + cagr/sector_finance/prosperity/zxm_tags/stock_profiles）｜**用户与日志**（7）。

### 4.2 API 设计（`GET /api/governance/tables`）

```json
{
  "total": 32,
  "rows": [
    {
      "table_name": "ads_stock_latest",
      "table_comment": "个股最新快照",
      "category": "预计算分析",
      "source": "系统计算(compute_ads.py)",
      "row_count": 5570,
      "latest_date": "2026-06-30",
      "latest_date_col": "report_date",
      "column_count": 27,
      "updated_at": "2026-08-11 09:32",
      "has_lineage": true
    }
  ]
}
```

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/governance/tables` | GET | 全量资产列表；支持 `?category=预计算分析&q=ads&sort=latest_date` |
| `/api/governance/tables/suggest` | GET | 自动提示：`?q=ads` → 前缀匹配英文名 / 模糊匹配中文名，返回前 8 条 `{table_name, table_comment, category}` |
| `/api/governance/tables/{table}` | GET | 单表详情（基本元数据 + 上游/下游表数 + 最近刷新记录） |
| `/api/governance/tables/{table}/columns` | GET | 列清单：`{column_name, column_comment, data_type}`，**列注释为空时回退到 data_catalog_meta.description** |
| `POST /api/governance/meta/{table}` | POST | 编辑中文名/分类/来源/说明（Pydantic body，`execute()` 写入） |
| `POST /api/governance/refresh` | POST | 重跑新鲜度统计（可选；默认每次请求实时查 MAX()） |

错误处理遵循现有约定：软错误 `return {'error': 'table not found'}`。

### 4.3 页面设计（数据资产目录页）

- **顶部搜索框**：输入前缀（如 `ads`、`财务`、`kline`）实时提示下拉（150ms 防抖，复用 `stock-suggestions` 交互），显示 `英文表名 + 中文名 + 分类badge`。
- **分类筛选条**：横向 chips（全部/行情/财务/板块与股本/预计算分析/用户与日志），复用 `.screening-stage-btn` 样式。
- **主表格**：英文表名 | 中文名 | 分类 | 数据来源 | 行数 | **最新数据日期**（颜色区分新鲜/滞后）| 最近刷新 | 操作。
- **行点击 → 列详情抽屉**：展示该表全部列（列名 + 注释 + 类型），"查看血缘"按钮跳转血缘页。
- 复用现有组件类：`.topbar`、`.card`、`.table-wrap`、`.dm-grid`、`.dm-status-text`、`.stock-suggestion*`；新类统一 `.dg-*` 前缀。

## 5. 数据血缘设计

### 5.1 血缘元数据表：`data_lineage`

```sql
CREATE TABLE IF NOT EXISTS data_lineage (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  source_table  VARCHAR(64) NOT NULL COMMENT '上游表',
  source_column VARCHAR(64) NOT NULL COMMENT '上游字段（表级血缘时为空串）',
  target_table  VARCHAR(64) NOT NULL COMMENT '下游表',
  target_column VARCHAR(64) NOT NULL COMMENT '下游字段（表级血缘时为空串）',
  transform     VARCHAR(16) NOT NULL DEFAULT 'direct' COMMENT '转换类型：direct/derive/aggregate/join/lookup',
  formula       VARCHAR(512) NOT NULL DEFAULT '' COMMENT '计算表达式，如 core_profit/operating_revenue*100',
  note          VARCHAR(255) NOT NULL DEFAULT '' COMMENT '口径说明',
  KEY idx_target (target_table, target_column),
  KEY idx_source (source_table, source_column)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据血缘边（表级+字段级）';
```

- **表级血缘**：`source_column=''` 的边，如 `fin_income → ads_stock_annual`、`ads_stock_latest → ads_sector_latest`。
- **字段级血缘**：`target_column` 非空的边，如 `ads_stock_annual.core_margin ← fin_income.operating_revenue`。

### 5.2 血缘配置源：`config/lineage.yaml`（核心资产）

由 `compute_ads.py` 的映射整理而成，示例（节选）：

```yaml
tables:
  - name: ads_stock_annual
    comment: 每股票×每年度财务
    upstream:
      - fin_income            # 利润表：营收/成本/费用/净利
      - fin_balance_sheet     # 资产负债表：资产/负债/现金/应收/存货
      - fin_cash_flow         # 现金流量表：经营现金流
      - ads_stock_annual      # 自连接算同比(YoY)
    fields:
      - {name: stock_code,     from: [fin_income.stock_code],           transform: direct}
      - {name: gross_profit,   from: [fin_income.operating_revenue, fin_income.operating_cost],
         transform: derive, formula: "operating_revenue - operating_cost"}
      - {name: core_profit,    from: [fin_income.operating_revenue, fin_income.operating_cost,
                                      fin_income.selling_expense, fin_income.admin_expense],
         transform: derive, formula: "revenue - cost - sell - admin"}
      - {name: core_margin,    from: [ads_stock_annual.core_profit, fin_income.operating_revenue],
         transform: derive, formula: "core_profit / operating_revenue * 100"}
      - {name: net_cash,       from: [fin_balance_sheet.cash, fin_balance_sheet.trading_fa,
                                      fin_balance_sheet.short_term_borrow, fin_balance_sheet.long_term_borrow],
         transform: derive, formula: "cash + tfa - short_borrow - long_borrow"}
      - {name: roe,            from: [fin_income.parent_net_profit, fin_balance_sheet.total_equity],
         transform: derive, formula: "parent_net_profit / total_equity * 100"}
      - {name: revenue_yoy,    from: [ads_stock_annual.operating_revenue], transform: derive,
         formula: "本年/上年-1", note: "同股票 report_date 减一年自连接"}
  - name: ads_stock_latest
    comment: 每股票最新快照
    upstream: [fin_income, ads_stock_annual, daily_kline, stock_shares_dfcf, stock_dividend, stocks]
    fields:
      - {name: market_cap,     from: [daily_kline.close_price, stock_shares_dfcf.total_shares],
         transform: derive, formula: "latest_price * total_shares / 1e8（亿元）"}
      - {name: pe_ttm,         from: [market_cap, fin_income.parent_net_profit], transform: derive,
         formula: "市值 / TTM归母净利", note: "TTM=最新报告期累计+上年年报-上年同期累计"}
      - {name: dividend_yield, from: [stock_dividend.dividend_yield, daily_kline.close_price],
         transform: lookup, note: "取 assign_progress='实施分配' 的最新一条"}
      - {name: roe_ttm,        from: [ads_stock_annual.roe], transform: direct,
         note: "⚠ 已知问题：当前实现=roe（非TTM），见 compute_ads.py:426"}
  - name: ads_sector_annual
    comment: 每板块×每年度汇总（二级聚合）
    upstream: [ads_stock_annual, stock_sectors, sectors]
    fields:
      - {name: total_revenue,    from: [ads_stock_annual.operating_revenue], transform: aggregate, formula: "SUM"}
      - {name: avg_gross_margin, from: [ads_stock_annual.gross_margin],      transform: aggregate, formula: "AVG"}
  - name: ads_sector_latest
    comment: 每板块最新快照（二级聚合）
    upstream: [ads_stock_latest, ads_sector_annual, stock_sectors, sectors]
```

初始化脚本 `src/init_governance.py` 读取该 YAML → 全量清空重灌 `data_lineage`（幂等）。

### 5.4 页面设计（数据血缘页）

- **入口**：顶部输入框（复用搜索提示）直接选表，或从资产目录页跳转（`window._lineageTable` 模式，沿用现有跨页导航约定）。
- **表级血缘图**：引入 **Cytoscape.js**（CDN，`https://unpkg.com/cytoscape@3.30.x/dist/cytoscape.min.js`，现有 SPA 已有多 CDN 脚本先例），渲染有向 DAG：
  - 节点 = 表，按数据分层着色：原始层（行情/财务，灰蓝）→ 聚合层（ads_stock_*，金）→ 汇总层（ads_sector_*，紫）；高亮目标表节点。
  - 边 = 生成关系，箭头指向下游；边标签显示关系摘要（SUM/derive/lookup）。
  - 点击节点 → 该表列清单面板（字段名 + 注释），点击字段触发字段级视图。
  - 缩放/拖拽/适配视窗按钮；空态引导。
- **字段级血缘图**：进入字段视图后，以**选中字段为中心**渲染其上游源字段链 + 下游消费字段链（各最多 2 跳），节点显示 `表.字段` 与中文注释，边标注公式。
- **血缘详情侧栏**：当前字段的完整公式、口径说明、已知问题（如 roe_ttm 标注）。
